This section defines the boundaries of the STAR Robot project, clearly establishing what is included and excluded from the project deliverables. The STAR Robot is a LiDAR SLAM robot with remote control capabilities designed for autonomous indoor mapping.

    \item \textbf {
  Hardware Platform
}
\begin { itemize }
        \item Custom PETG/aluminum chassis with high-compliance wheel drive
        \item SICK TiM561 2D LiDAR: 270° FoV, 10m range, 15Hz scan rate, $\pm$60mm accuracy (donated, \$3,500 value including cables)
        \item RPLiDAR C1 2D LiDAR (backup/development): 360° FoV, 12m range, 10Hz scan rate, $\pm$30mm accuracy, \$55
        \item Ultrasonic/sonar sensors for obstacle detection redundancy and DWA (Dynamic Window Approach) local planner interruption, a real-time collision avoidance algorithm that evaluates safe velocity trajectories
        \item DS18B20+ temperature sensor for HC-SR04 ultrasonic calibration, enabling speed-of-sound compensation ($v = 331.3 + 0.606 \cdot T$) to improve distance measurement accuracy from $\pm$3\% to $\pm$0.5\%
        \item NTC thermistors integrated into power management ICs for motor driver and battery thermal monitoring with automatic safety shutdown
        \item Raspberry Pi 5 compute platform (high-level processing)
        \item ESP32-S3 microcontroller operating as SPI peripheral to Raspberry Pi 5, responsible for DS18B20+ temperature sensing and motor control via DRV8243-Q1 drivers using hardware MCPWM (Motor Control Pulse Width Modulator)
        \item BNO055 IMU connected to Raspberry Pi 5 via I\textsuperscript{2}C for orientation sensing with onboard sensor fusion
        \item LiPo battery power system with fuel gauge monitoring (low-level control via SMBus)
        \item DRV8243-Q1 motor drivers (4x automotive-grade H-bridge) configured by ESP32 via SPI at boot, then controlled via EN (direction) and PH (speed) PWM signals; encoder feedback at 100Hz for closed-loop velocity control
        \item HC-SR04 ultrasonic sensors (7x) connected to Raspberry Pi 5 GPIO for close-range obstacle detection (2--400 cm)
        \item A7670G 4G LTE cellular module for remote connectivity and telemetry
        \item Power management system: USB-C DRP(Dual-Role Power) PD(Power Delivery) port with buck-boost charger for LiPo battery charging, fuel gauge (BQ78350) for state-of-charge monitoring, and regulated 6V/5V/3.3V rails for system power
    \end{itemize}

        \subsubsection{What is NOT Included}

                The following items are explicitly excluded from the project
                    scope :

            %
            5 / 12 This has been reviewed -
            Brighton
\begin {
          itemize
        }
    \item \textbf{Outdoor Operation}: The system is designed for indoor, structured environments only. Outdoor terrain, weather resistance, and GPS integration are excluded.

    \item \textbf{Manipulation Capabilities}: No robotic arm, gripper, or object manipulation functionality is included.

    \item \textbf{Multi-Robot Coordination}: The project focuses on a single-robot system. Swarm behavior and multi-robot communication are excluded.

    \item \textbf{Paid Cloud-Based Processing}: All computation occurs on-board. Cloud connectivity and remote processing are excluded; a local web-based interface for map visualization is included.

    \item \textbf{3D Reconstruction}: Our 2D LiDAR sensors (SICK TiM561, RPLiDAR C1) scan in a single horizontal plane and cannot generate 3D volumetric data. The system produces 2D occupancy grid maps only.

    \item \textbf{Machine Learning Training}: Pre-trained models may be used, but custom ML model development is excluded. Locked Inc. will finetune models, but not create any from scratch.

    \item \textbf{Return-to-home functionality}: Autonomous return-to-origin requires accurate long-term odometry which is subject to cumulative drift errors. The system relies on manual teleoperation via remote control for return navigation, which provides more reliable control in the prototype stage.
\end{
      itemize
    }

    \subsection{Test Methods}

            Each requirement has an associated test method to verify compliance
        :

        %
        5 / 12 This has been reviewed -
        Brighton Detailed test procedures,
        acceptance criteria,
        and validation results are documented in the Implementation
            section(see \Cref{sec : test_plan}) and
            the Test Plan section(Table ~\ref{tab : test_strategy})
                .

\begin {
      enumerate
    }
    \item \textbf{Navigation Test}
        : Robot navigates predefined path in lab environment;
    success measured by completion without human intervention.

    \item \textbf{Obstacle Avoidance Test}
        : Course with obstacles of various sizes;
    robot must detect and avoid all obstacles above 10cm threshold.

    \item \textbf{Mapping Accuracy Test}
        : Map generated room with known dimensions;
    compare generated map to laser -
        measured ground truth.

    \item \textbf{Sensor Validation}
        : Verify LiDAR reports valid data across full 360 -
        degree range with no blind spots.

    \item \textbf{Endurance Test}
        : Continuous operation under typical navigation workload until battery
              depletion;
    measure total runtime.

    \item \textbf{Performance Monitoring} : Log CPU, memory,
        and sensor rates during operation using \texttt {
      ros2 topic hz
    } for
      message rates \parencite{ros2_documentation}, \texttt {
        diagnostic\_common\_diagnostics
      } for
      system health \parencite{ros2_diagnostic_common}, and \texttt { htop } for
      process - level resource usage.
\end { enumerate }
