\subsection{Motor Control Architecture}

\subsubsection{GPTW vs MTU Selection for PWM Generation
}

The RX72N provides two timer peripherals suitable for motor control PWM generation: the General PWM Timer (GPTW) and the Multi-Function Timer Unit (MTU). After detailed analysis, \textbf{GPTW was selected
} for
  the following technical reasons :

\textbf{Resolution and Performance:
 }
\begin{itemize}
\item \textbf{GPTW:
}
32 - bit timer resolution enabling precise duty cycle control
    \item \textbf{MTU:
}
16 - bit timer resolution(65, 536 maximum count)
    \item At 20 kHz PWM frequency with 120 MHz peripheral clock :
    \begin{itemize}
\item GPTW provides 6, 000 discrete duty cycle steps(120 MHz / 20 kHz)
        \item MTU limited to maximum 3, 276 steps before counter overflow
    \end{itemize}
\end{itemize}

\textbf{Channel Architecture:}
\begin{itemize}
\item \textbf{GPTW:
}
4 independent channels,
    each with 2 complementary outputs(GTIOC0A / B through GTIOC3A / B)
    \item \textbf{Perfect match
} for
4 motors in \texttt{IN2} / \texttt{IN1} (sign-magnitude) control mode
    \item Each motor driver(\texttt{DRV8263H})
      requires exactly 2
    PWM signals
\end{itemize}

\textbf{Peripheral Separation:}
\begin{itemize}
    \item Using GPTW for PWM provides dedicated high-resolution motor control
    \item Encoders use MTU (front wheels) and TPU (rear wheels) for phase counting
    \item No resource conflicts between PWM generation and encoder reading
\end{itemize}

    \textbf{Encoder Peripheral Selection:}
    \begin{itemize}
    \item \textbf{Front encoders (0, 1)}: MTU1/MTU2 - 32-bit counters with phase counting support
    \item \textbf{Rear encoders (2, 3)}: TPU1/5, TPU2/4 - 16-bit counters with phase counting support
    \item \textbf{IMPORTANT}: MTU3 and MTU4 do NOT support phase counting mode per RX72N Manual Ch24 \S24.1.2
    \item Only MTU1 and MTU2 have phase counting capability, hence TPU required for rear encoders
    \item TPU provides adequate performance for 210 RPM max speed (13.7s overflow period with 16-bit counter)
    \item Software overflow detection at 100 Hz control loop provides 137$\times$ safety margin
\end{itemize}

    \textbf{Pin Flexibility:}
    \begin{itemize}
    \item GPTW signals available on multiple pin locations via
    MPC(Multi - Function Pin Controller)
    \item Example : GTIOC0A available on pins 34,
                     90,
                     106,
                     123
    \item Enabled conflict - free allocation by selecting alternate pin groups
\end{itemize}

    \subsubsection{Pin Allocation Strategy}

    \textbf{Design Philosophy:}
    \begin{enumerate}
    \item \textbf{Peripheral Grouping :
   } Place related functions on contiguous port pins where possible
    \begin{itemize}
    \item \texttt{GPTW} PWM (\texttt{IN1}/\texttt{IN2}) : Motors spread across PORT E, PORT C, and PORT P (pins 34, 35, 38, 41, 61, 67, 101, 108)
        \item Motor Driver GPIO (\texttt{DRVOFF}/\texttt{nSLEEP}) : PORT E and PORT P6x (pins 109-115, 117)
        \item Host SPI to RPi5 : PD1 - PD4 (RSPI2\_A, pins 122 - 125)
        \item MTU Encoders : P24 / P25 (MTU1), PA1 / PC5 (MTU2)
        \item TPU Encoders : PC2 / PA3 (TPU1), PC0 / PB3 (TPU2)
        \item I2C : P12 - P13 (RIIC0 Host RPi5), P20 - P21 (RIIC1 IMU)
    \end{itemize}

    \item \textbf{Conflict Resolution via Alternate Functions:}
    \begin{itemize}
        \item 144-pin package provides more pins, reducing conflicts vs.\ 100-pin
        \item Table 1.9 analysis revealed all peripherals have 2-4 alternate pin locations
        \item GTETRG inputs used as PWM external triggers (GTETRGA/B/C/D on pins 42, 89, 66, 43)
        \item RIIC1 (P20/P21) repurposed for IMU after BMS removal
        \item Motor driver GPIO (\texttt{DRVOFF}/\texttt{nSLEEP}) placed on PORT E and PORT P6x to keep routing compact
    \end{itemize}

        \item \textbf{PCB Routing Optimization:}
        \begin{itemize}
        \item Host SPI signals on PD1-PD4 (pins 122-125) for compact layout
        \item Motor PWM (\texttt{IN1}/\texttt{IN2}) and driver GPIO (\texttt{DRVOFF}/\texttt{nSLEEP}) on PORT E and PORT P6x
        \item Sonar sensors grouped on pins 4-13 (top of package)
        \item ADC current sense on P44-P47 (pins 133-136) for short analog traces
    \end{itemize}

        \item \textbf{Future Expandability:}
        \begin{itemize}
        \item 43 GPIO pins available after critical allocations (of 144 total)
        \item Unused Port D pins (PD5-PD7) available for additional QSPI/SDHI
        \item Port E pins split between motor PWM (PE3, PE7), motor GPIO (PE0-PE2), and available GPIO (PE4-PE6)
        \item Ethernet pins (Port B/P7x) available for future network connectivity
        \item Additional ADC channels available (AN000-AN003, AN100-AN117)
    \end{itemize}
        \end{enumerate}

        \subsubsection{Communication Bandwidth Analysis}

\textbf{SPI Configuration: 10 Mbps is Optimal}

Peak bandwidth calculation for RPi5 $\leftrightarrow$ RX72N communication:
\begin{itemize}
\item \textbf{Velocity Commands(100 Hz) :}
\begin{itemize}
\item Message size : 34 bytes(Nanopb encoded MotorVelocityCommand)
        \item Bandwidth : $34 \text {
  bytes
}
\times 100 \text { Hz}
\times 8 = 27.2 \text{Kbps} $
    \end{itemize}

\item \textbf{Encoder Feedback(100 Hz) :}
\begin{itemize}
\item Message size : 18 bytes(4 encoders $\times$ 4 bytes + header)
        \item Bandwidth : $18 \text {
  bytes
}
\times 100 \text { Hz}
\times 8 = 14.4 \text{Kbps} $
    \end{itemize}

\item \textbf{Telemetry(50 Hz) :}
\begin{itemize}
\item Message size : 64 bytes(battery, motor current, temperature, status)
        \item Bandwidth : $64 \text {
  bytes
}
\times 50 \text { Hz}
\times 8 = 25.6 \text{Kbps} $
    \end{itemize}

\item \textbf{ARQ Protocol Overhead(estimated 40\%) :}
\begin{itemize}
\item Headers : 8 bytes per frame(sequence, CRC - 32, flags)
        \item Retransmissions : Average 5\% packet loss $\times$
                                 3 retry attempts
        \item Total overhead : $(27.2 + 14.4 + 25.6) \times
                                1.4 = 94.1 \text{Kbps} $
    \end{itemize}
\end{itemize}

\textbf{Total Peak Bandwidth :} $$\text{Peak} = 27.2 + 14.4 + 25.6 +
                                                 94.1 = \textbf{161.3 Kbps} $$

\textbf{SPI Utilization :
} $$\frac{161.3 \text{Kbps}} {10 \text{Mbps}} = \textbf{1.6\% utilization} $$

\textbf{Margin Analysis:
}
\begin{itemize}
    \item Available headroom: $10,000 / 161.3 = 62\times$ current requirements
    \item No need for Ethernet (would add PHY chip, 9+ pins, PCB complexity)
    \item No need for QSPI (RPi5 doesn't support quad-lane SPI natively)
    \item 10 Mbps provides excellent margin for future features (camera data, additional sensors)
\end{itemize}

\subsubsection{DS18B20+ Temperature Sensor}

The DS18B20+ is a digital 1-Wire temperature sensor connected to P51 (pin 55).

\textbf{Specifications:}
\begin{itemize}
    \item \textbf{Temperature Range:} -55\textdegree C to +125\textdegree C
    \item \textbf{Accuracy:} \textpm 0.5\textdegree C from -10\textdegree C to +85\textdegree C
    \item \textbf{Resolution:} 9-bit to 12-bit configurable (0.5\textdegree C to 0.0625\textdegree C)
    \item \textbf{Interface:} 1-Wire protocol on DQ pin (P51)
    \item \textbf{Power:} Parasite power or separate VDD (3.0V to 5.5V)
\end{itemize}

\textbf{Pin Connections:}
\begin{itemize}
    \item \textbf{DQ (Data):} P51 (pin 55) - 1-Wire data line
    \item \textbf{VDD:} 3.3V power supply
    \item \textbf{GND:} Ground
\end{itemize}

\textbf{Required External Components:}
\begin{itemize}
    \item 4.7k$\Omega$ pull-up resistor on DQ line (P51 to 3.3V)
    \item 0.1$\mu$F decoupling capacitor near VDD pin
    \item Optional: 100nF ceramic capacitor if using parasite power mode
\end{itemize}

\textbf{Firmware Implementation:}
\begin{itemize}
    \item Use 1-Wire protocol library (timing-critical, requires precise delays)
    \item Typical read cycle: 750ms for 12-bit conversion
    \item Multiple sensors can share same 1-Wire bus (each has unique 64-bit ROM code)
\end{itemize}

\textbf{Use Cases:}
\begin{itemize}
    \item Ambient temperature monitoring
    \item Motor driver thermal management (supplement \texttt{DRV8263H} internal temp)
    \item System enclosure temperature
\end{itemize}

\subsection{IMU}

The IMU is connected to the RX72N via I2C with a dedicated interrupt and reset line.

\textbf{Pin Connections:}
\begin{itemize}
    \item \textbf{SCL (Clock):} P21 (pin 36) --- I2C clock (RIIC1)
    \item \textbf{SDA (Data):} P20 (pin 37) --- I2C data (RIIC1)
    \item \textbf{INT (Interrupt):} P32 (pin 27) --- active-low interrupt output from IMU to RX72N IRQ input
    \item \textbf{RST (Reset):} P83 (pin 58) --- active-low reset, driven as GPIO output by RX72N
    \item \textbf{VDD:} 3.3V power supply
    \item \textbf{GND:} Ground
\end{itemize}

\textbf{Required External Components:}
\begin{itemize}
    \item 4.7k$\Omega$ pull-up resistors on SCL and SDA lines (to 3.3V)
    \item 100nF decoupling capacitor near VDD pin
\end{itemize}

\textbf{Firmware Implementation:}
\begin{itemize}
    \item Configure INT pin as IRQ input (falling-edge triggered)
    \item Assert RST low for $\geq$10\,ms at startup to perform a hardware reset before initialisation
    \item Use I2C to read sensor data registers on each INT assertion
\end{itemize}

\subsection{Motor Driver Control Architecture}

The \texttt{DRV8263H} motor drivers are controlled via three interfaces:

\textbf{Real-Time Control (PWM):}
\begin{itemize}
    \item \textbf{Signals:} \texttt{IN1} and \texttt{IN2} distributed across \texttt{GPTW} channels 0-3
    \item \textbf{Purpose:} Motor speed/direction control at 20 kHz PWM frequency
    \item \textbf{Update rate:} 100 Hz velocity commands from RPi5
    \item \textbf{Pin mapping:} \texttt{IN2} = \texttt{GTIOC\_A}, \texttt{IN1} = \texttt{GTIOC\_B} (sign-magnitude PWM)
\end{itemize}

\textbf{Driver Enable/Sleep Control (GPIO):}
\begin{itemize}
    \item \textbf{\texttt{DRVOFF} signals:} PE2 (Motor 3), PE0 (Motor 2), P63 (Motor 1), P61 (Motor 0)
    \item \textbf{\texttt{nSLEEP} signals:} PE1 (Motor 3), P64 (Motor 2), P62 (Motor 1), P60 (Motor 0)
    \item \textbf{\texttt{DRVOFF} purpose:} Disable H-bridge outputs without entering sleep mode (GPIO output)
    \item \textbf{\texttt{nSLEEP} purpose:} Put driver into low-power sleep mode when pulled low (GPIO output, active-low)
    \item \textbf{Update rate:} On demand for enable/disable/sleep transitions
\end{itemize}

\textbf{External PWM Triggers (GTETRG):}
\begin{itemize}
    \item \textbf{Signals:} GTETRGA (pin 42), GTETRGB (pin 89), GTETRGC (pin 66), GTETRGD (pin 43)
    \item \textbf{Purpose:} GPTW external trigger inputs for synchronised PWM control
\end{itemize}
