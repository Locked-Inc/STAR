52.

2D Drawing Engine (DRW2D)

52.1

Overview

This MCU incorporates a 2D drawing engine (DRW2D). Table 52.1 lists the DRW2D specifications.
Table 52.1

DRW2D Specifications

Item

Descriptions

Vector drawing engine

Extended rendering primitives supported in hardware
 Lines
 Polygons
 Circles and ellipses
 Quadratic Béziers
 Texture mapping

BitBLT function

Seven types of BitBLT operations
 Fill
 Copy
 Stretch BitBLT
 Rotate and scale
 Alpha blending
 Bilinear filtering
 Color conversion

Color format

Frame buffer

Four types
 A(8)
 RGB(565)
 ARGB(4444)
 ARGB(8888)

Texture

11 types
 CLUT(1)
 CLUT(2)
 CLUT(4)
 CLUT(8)
 A(8)
 ACLUT(44)
 RGB(565)
 ARGB(4444)
 ARGB(1555)
 RBG(888)
 ARGB(8888)

Texture

 Run-length encoding (RLE) unit
 256-entry color look-up table (CLUT)
 Chroma keying unit

Render

Two modes for rendering process
 Register mode
 Display list mode

Data arrangement

Little endian

Performance counter

 Two independent 32-bit counters
 Trigger is selectable from 14 events

Interrupt sources

Two interrupt sources
 Enumeration finished interrupt (DRWENUIR)
 Display list finished interrupt (DRWDLIR)

The DRW2D provides two inputs (texture read and frame buffer read) and one output (frame buffer write). The internal
color format is always ARGB(8888). The color formats from the inputs are converted to the internal format on read and
converted back on write.
Figure 52.1 shows examples of objects that can be drawn in hardware with the DRW2D and Figure 52.2 shows the
block diagram of the module.

52.3

52. 2D Drawing Engine (DRW2D)

Drawing Features

52.3.1

Drawing Features Summary

52.3.1.1

Color Formats

Supported color formats are:
Frame Buffer formats
 8-bit: A(8)
 16-bit: RGB(565), ARGB(4444)
 32-bit: ARGB(8888)
Texture formats
 1-bit: CLUT(1)
 2-bit: CLUT(2)
 4-bit: CLUT(4)
 8-bit: A(8), CLUT(8), ACLUT(44)
 16-bit: ARGB(4444), ARGB(1555), RGB(565)
 24-bit: RGB(888) (RLE unit)
 32-bit: ARGB(8888)
CLUT formats use a 256-entry color lookup table.

52.3.1.2

Vector Drawing Features

The vector drawing engine uses a half-plane rendering approach, which simplifies implementation of edge anti-aliasing
and blurring features without much overhead. When combining some of its functional units, the module can draw not
only linear primitives such as lines or polygons, but also quadratic equation-based primitives such as circles and
ellipsoids. The following primitives and texture mapping are supported:
 Lines
 Polygons
 Circles and ellipses
 Quadratic curves (software driver support)
 2D texture mapping
 Bilinear filtering of the textures

52.3.1.3

BitBLT Features

The DRW2D supports the BitBLT features using its vector drawing function to draw a rectangle and texture it based on
the selected BitBLT function. This approach results in the following BitBLT features:
 Fill
 Copy
 Stretch BitBLT
 Rotate and scale
 Alpha blending
 Bilinear filtering
 Color conversion

52.4

52. 2D Drawing Engine (DRW2D)

Rendering Modes

The rendering process can be performed in two different modes, register mode and display list mode.

52.4.1

Register Mode

In register mode, when operation is based on register settings, the CPU configures and initiates each render process
separately. To start a new render process, the CPU must wait until the previous one is completed. In this mode, the CPU
is heavily engaged throughout the entire drawing procedure and is consequently to a large extent unavailable for other
tasks.
The CPU must set up all registers for performing a certain drawing operation before it can start the rendering process. A
new register setup can only be started when the previous render process has completed. Before starting a new register
setup, make sure that:
 STATUS.DLSTACT = 0: Display list reader is idle
 STATUS.BSYENUM = 0: Pixel selection unit is idle.
Lastly, write the frame buffer start address to the ORIGIN register. This write triggers the DRW2D to start rendering.

52.4.2

Display List Mode

In display list mode, the CPU creates a display list in memory prior to starting the DRW2D. Such a display contains a
bundle of render operations. When started, the DRW2D executes the display list autonomously in parallel with the CPU,
which is not involved with drawing operations most of the time. Use of a display list allows a fully asynchronous
operation of the CPU and the DRW2D and offers the best possible system performance.
In this mode, the display list reader reads a memory block containing instructions on how to set the DRW2D control
registers and executes these control register writes accordingly.

52.5

52. 2D Drawing Engine (DRW2D)

Interrupts

The DRW2D generates two interrupts:
 DRWENUIR interrupt
 DRWDLIR interrupt

52.5.1
(1)

Interrupt Sources

DRWENUIR Interrupt

This is the current render process finished interrupt.

(2)

DRWDLIR Interrupt

This is the display list finished interrupt. It is asserted on completion of a display list process. DRWDLIR is activated if
one of the following is true:
 The entire display list is complete
 The display list processing stops because a new display list start is triggered by a write to the DLISTST register.

52.5.2

Interrupt Control

The two DRW2D interrupts are combined into a single shared interrupt, DRWIRQ, to the CPU. Each interrupt can be
disabled or enabled by setting its associated enable bit in the IRQCTL register.
The occurrence of an enabled interrupt (one with its enable bit set to 1 in the IRQCTL register) is monitored in the
STATUS register with its associated interrupt status bit is set to 1. The shared DRW2D interrupt DRWIRQ is then
generated.
To clear the interrupt, write 1 to the interrupt clear bit in the IRQCTL register. The interrupt clear bit returns to 0
automatically.

Notes for Endian Setting

DRW2D accesses a memory on the premise that all data are stored in little-endian format. When using the DRW2D, set
