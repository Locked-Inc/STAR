51.1.1

GLCDC Structure

Figure 51.2 shows the structure of the GLCDC.
The GLCDC includes the following blocks:
 Background generating block:
Generates the background screen (including the blanking interval), specifies the background color,
and generates the synchronization signals for controlling the screens.
 Graphics data interface blocks (2 blocks):
Convert the graphics data read from the frame buffer into ARGB(8888) data for internal
processing, and perform asynchronous data transfer from peripheral module clock (PCLKA)
domain to pixel clock (PXCLK) domain.
 Alpha blending blocks (2 blocks):
Combine graphics data with the lower-layer screen and perform alpha blending based on the
register settings and the alpha values in the current graphics data.
 TCON block:

Generates the vertical and horizontal synchronization and enable signals suited for the
specifications of the connected LCD panel, from the internal vertical and horizontal
synchronization signals.

The GLCDC reads the frame buffer in 64-byte units, so set the GRnFLM2 register and the LNOFF[10:0] bits to
multiples of 64.
The width and height of the frame buffer should be set to at least the numbers obtained by (DATANUM[15:0] + 1) × 64

The following is an example of settings when the frame buffer size is 1024 pixels × 512 lines, the active display size is
480 pixels × 272 lines, and the color format is CLUT(8).
LNOFF[15:0] = 1024 × 1 = 1024 = 0400h
DATANUM[15:0] = round(480 × 1 ÷ 64) – 1 = 7 = 0007h
LNNUM[10:0] = 272 – 1 = 271 = 10Fh
GRCHW[10:0] = 480 = 1E0h
GRCVW[10:0] = 272 = 110h
In this case, data for 512 pixels are read from the frame buffer per line. The data for 32 pixels (invalid data) which are
beyond the value set in the GRCHW[10:0] bits are discarded.

Output Control (TCON)

Any of the five signals (STVA, STVB, STHA, STHB, and DE) generated from the internal vertical and horizontal
synchronization signals (VS and HS) that have passed through the data format conversion block can be selected for

The generated signals are completely independent of the image data. They are not affected by the output image format or
any internal data process, and no register settings for signal generation affect the output image format or any internal data
process. The data enable signal DE, which is to be generated by the TCON block, is the logical AND of the two signals
STVB and STHB, which were previously generated by the TCON block. In general, three signals, which includes the
signals corresponding to the VS and HS signals plus the DE signal, are used to output the DE signal.

51.1.8

51. Graphic LCD Controller (GLCDC)

Graphics Data Interfaces

Two circuits (graphic 1 and 2) are provided for reading graphics data, each of which incorporates an access control block,
data buffer, CLUT memory, data extension block, and clock domain crossing block.

(1)

Access Control Block

After release from the reset state, when the necessary register settings are made and operation of the GLCDC is enabled,
this block waits for the input of the VS (vertical synchronization) signal. Every time the VS signal is asserted, the
internal states are initialized and access to internal main bus 2 proceeds. Internal main bus 2 is read in 16-beat increments
and in 32-bit units (4 bytes × 16 beats = 64 bytes). All read data are stored in the data buffer, including the invalid data at
the end of the line.

(2)

Data Buffer

The data buffer is read via a 64-bit read buffer. Reading of the invalid data at the end of the line is skipped. The upper bit
in the data stored in the read buffer is used for access to CLUT or data extension, the next data is filled from the data
buffer. Filling data to the read buffer takes precedence over writing to the data buffer in case of a conflict.

(3)

CLUT Memory

When the pixel data read from the data buffer contains CLUT indices (addresses for accessing to the CLUT memory),
the GLCDC accesses to the CLUT memory by reading the corresponding data as the addresses, and stores all read data
(in the ARGB(8888) format) or only alpha values (in case of ARGB(1555)) in the buffer of the clock domain crossing
block.
Write the data in the CLUT memory via internal peripheral bus.

(4)

Data Extension Block

If the pixel data read from the data buffer contains the directly color data, the GLCDC sends the corresponding data to
the data extension block. The block extends the data in the ARGB(8888) format and stores them in the buffer of the clock
domain crossing block.
When the data contain both of the CLUT indices and direct color data (in case of ARGB(1555)), an A value obtained
from the CLUT memory is combined with an RGB value acquired from the data extension block, and is stored in the
buffer of the clock domain crossing block.

(5)

Clock Domain Crossing Block

This block is a circuit which performs asynchronous transfer of the pixel data (in the ARGB(8888) format) from the
peripheral module clock (PCLKA) domain to the pixel clock (PXCLK) domain. The block is composed of a 4-pixel ring
buffer. When data for 1 pixel are transferred to the alpha blending block, a sequence of operations consisting of reading
from the read buffer, access to CLUT memory, extension of data, combining graphics data, and storage in the ring buffer
proceeds with steps included as required, after which 1 pixel data is filled.

Blending

The following three types of processing proceed for the graphics areas specified in the registers. The lower-layer
graphics or the background color data of current graphics is output without any processing in the display area outside the
graphics area.
 Display screen selection
 RGB reference chroma key
 Alpha blending

(1)

Display Screen Selection

Based on the GRnAB1.DISPSEL[1:0] bits settings (n = 1, 2), any of the following data is output to the graphics area:
 Background color:

Image data specified in the GRnBASE register.

 Lower-layer graphics: Image data input from the previous block
Output from the background generating block for graphic 1
Output from graphic 1 for graphic 2
 Current graphics:

Image data obtained from the graphics data interface block extending the pixel data read by
the graphic 1 or 2 block via the internal main bus 2 to ARGB(8888) format data.

 Blending:

Image data obtained by blending current graphics data and the lower-layer graphics data
based on the alpha values or the register settings.

It is possible to rewrite the GRnAB1 register while display operation is in progress. Setting the BGEN.VEN or
GRnVEN.VEN bit to 1 leads to a reflection of the update value to the internal operations when the VS (vertical
synchronization) signal is asserted.

(2)

RGB Reference Chroma Key

If the RGB value of the ARGB(8888) data input from the graphics data interface block matches the value set in the
GRnAB8 register, the ARGB(8888) data is entirely replaced with the value preset in the GRnAB9 register. All the
ARGB(8888) data input from the graphics data interface block is subject to this process. If your application excludes
CLUT memory output from this process, set the GRnAB7.CKON bit to 0 (disable RGB reference chroma key).

(3)

Alpha Blending

If the GRnAB1.DISPSEL[1:0] bits are set to 11b (blending), current graphics and lower-layer graphics are alpha-blended
based on the register settings using either of the following two functions.

(a)

Rectangular Alpha Blending

The following process is performed for the rectangular area (in the graphics area) preset in the GRnAB4 and GRnAB5
registers:
(1) Current graphics is blended with the lower-layer graphics according to the A value set in the
GRnAB7.ARCDEF[7:0] bits.
(2) After processing of the number of frames specified in the GRnAB6.ARCRATE[7:0] bits, the value specified in the
GRnAB6.ARCCOEF[8:0] bits is added to or subtracted from A value.
(3) Current graphics is blended with the lower-layer graphics according to this updated A value.
(4) Repeat (2) and (3). The A value is clipped in the range from 0 to 255.

This register controls the GLCDC states. The internal states can be read from the BGMON register and BGEN.VEN.
Because the GLCDC, which operates on multiple clocks, requires a certain period for state transition, confirm that the

EN Bit (Background Generating Block Operation Enable)
The EN bit enables or disables the operation of the background generating block. When this bit is set to 0, the operation
of the entire GLCDC stops because the reference signal for internal operations generated by the background generating
block is no longer being generated.
When setting this bit to 1, set the BGEN.VEN bit to 1 simultaneously to enable register value reflection to internal
operations. When setting this bit to 0, set the BGEN.VEN bit to 0 at the same time.
When this bit is changed from 1 to 0, the operation stops at the end of screen generation, unlike the SWRST bit.
When setting this bit to 0, confirm that the BGMON.EN flag has become 0. Operation is not guaranteed if this bit and/or
the BGEN.VEN bit are set to 1, or if the settings in other registers are modified before the BGMON.EN flag becomes 0.
VEN Bit (Register Value Reflection Enable)
The VEN bit enables or disables reflection of the GLCDC internal register to the GLCDC internal operation on assertion
of the VS (vertical synchronization) signal.
When this bit is set to 1, the signal of GLCDC internal register values reflection control becomes 1 at the immediate start
of the background frame, and becomes 0 at the end of the vertical active pixel of the same frame. This internal signal can
be monitored with the BGMON.VEN flag. This bit becomes 0 at the same time as the VEN flag.
Set this bit to 1 only when this bit is 0. Operation is not guaranteed if this bit is set to 1 when 1. Also, while this bit is 1,
do not modify any register whose value is reflected to the internal operations at the start of the background frame or on
assertion of the VS signal. Otherwise, operation is not guaranteed.

underflow).

However, this flag automatically becomes 0 when the graphics data interface block is initialized on assertion of the VS
signal.
Even when the current graphics data is not required (the GRnAB1.DISPSEL[1:0] bits are 00b (background color) or 01b
(lower-layer graphics)), this flag becomes 1 during the period from the start of the graphics area to the assertion timing of
the VS signal for next frame. In addition, for the first frame after a software reset, this flag may become 1 before the VS
signal is asserted depending on the value set in the BGSYNC.VP[3:0] bits.

51.3.1.1

Start of Operation

The procedure for starting the GLCDC is described as follows.
(1) After releasing the GLCDC from the module stop state, set the BGEN.SWRST bit to 1 to release the GLCDC from
a software reset.
(2) Select the output data format. Set the frequency of the LCD_CLK and PXCLK to suit the format and set the
PANELCLK.CLKEN bit to 1. If frequency settings which are not suitable for the output data format are attempted,
operation is not guaranteed. Wait until PXCLK and LCD_CLK are supplied and the BGMON.SWRST flag
becomes 1.
(3) Set values in the registers that are required for operations. No particular rules apply to the order of setting of the
registers. However, do not set the BGEN.EN, BGEN.VEN, GRnVEN.VEN, GAMxVEN.VEN, OUTVEN.VEN,
and INTEN.GRnUFINTEN bits to 1 (n = 1, 2; x = G, B, R).
 When displaying the graphics data on the frame buffer by graphic 1 and 2, set 1 to the GRnFLMRD.RENB bit
(graphics data read enable).

51.3.1.2

Rewriting Registers During Operations

The GLCDC has registers, which values can be updated and reflected in internal operations without stopping the
operation of individual blocks. Setting the VEN bit to 1 in the block to be updated leads to a reflection of the value of an
updated register to the internal operations immediately after assertion of the VS signal.
However, if the contents of the CLUT memory in use (selected by the GRnCLUTINT.SEL bit) are changed, the value
will be reflected to the internal operations immediately after the change without waiting for assertion of the VS signal.
To update the value of the CLUT memory in synchronization with the VS signal, rewrite the contents of the CLUT
memory which is not in use, and then switch the CLUT memory to be used by using the GRnCLUTINT.SEL bit. After
that, set the BGEN.VEN bit or GRnVEN.VEN bit to 1.
The procedure for changing parameters during operations is as follows.
(1) Confirm that the VEN bit in the target block is 0. Operation is not guaranteed if the register is modified while the
VEN bit in the target block or the BGEN.VEN bit is 1.
(2) Rewrite the value of the target registers.
(3) To reflect the value of the register only in a target block, set the VEN bit of the block to 1. When the register values
in multiple blocks are to be reflected, set the BGEN.VEN bit to 1.
(4) Confirm that the VEN bit that was changed to 1 has returned to 0. Once the value of this bit is 0, the value of the
target register will have been reflected in internal operations. If this bit is still 1, then the change may not have been
reflected. In addition, the VEN bit in each block is cleared to 0 once the value of the target register is internally
reflected, but the BGEN.VEN bit will not be cleared to 0 until the VE signal is negated.

51.3.1.3

Stopping and restarting in normal operation

The procedure for stopping and restarting the GLCDC is as follows.
(1) Confirm that the VEN bit of each block is set to 0.
(2) Set the BGEN.EN bit to 0.
(3) Confirm that the BGMON.EN flag has been set to 0. Operation of the GLCDC has not stopped until the value of this
flag becomes 0. In addition, the EN flag is set to 0 at the end of the frame in the background generating block, not of
that in the signals output to the LCD panel. When completion of operation of all blocks is needed, wait for a certain
period (e.g. time equivalent to a single horizontal line) after the EN flag has been set to 0. In general, if the
BGEN.SWRST bit is set to 0 (software reset) immediately after confirming that the BGMON.EN flag has been set
to 0, there should not be any problems due to the vertical blanking interval.
(4) Set the BGEN.SWRST bit to 0 to apply a software reset to the GLCDC. Registers other than the CLUT memory are
initialized by a software reset.
(5) Start the GLCDC in accordance with section 51.3.1.1, Start of Operation.
When restarting the GLCDC after rewriting to a register without a software reset, wait till the end of the frame in the
output signals to the LCD panel before starting the GLCDC. There is no problem for the GLCDC itself to start operation
in response to the assertion of the VS signal. However, if the vertical blanking interval or a single horizontal line is short,
this may affect the operation of the LCD panel. For details, check the specifications of the LCD panel.

Figure 51.23 shows the changes in signal lines and flags for stopping and restarting normal operation. When access to

BGEN.EN bit is set to 0 to stop the background generating block.

Status Detection and Interrupts

The GLCDC can detect the three types of status described in this section. To detect each status, set the corresponding bit
in the DTCTEN register to 1.

51.3.3.1

Graphic n Underflow Detection (n = 1, 2)

This function is equipped with both graphic 1 and 2.
When the graphics data interface block fails to supply required graphic data to the alpha blending block (the valid data
was not stored in the 4-stage ring buffer), the STMON.GRnUF is set to 1. The underflow status in the graphic n is cleared
when the VS (vertical synchronization) signal is asserted, but the STMON.GRnUF flag is not cleared until the
STCLR.GRnUFCLR bit is set to 1.

51.3.3.2

Specified Line Detection

This function detects that the target of data to be processed by graphic 2 is the line specified in the
GR2CLUTINT.LINE[10:0] bits. In fact, the detection by using the VS and HS signals is applied regardless of whether
graphic 2 operations are actually to proceed. Detection proceeds on the assertion of the HS (horizontal synchronization)
signal, but not at the start of the processing of active pixels. Every time the HS signal for the specified line is asserted, the
STMON.VPOS flag is set to 1. To clear the STMON.VPOS flag, the STCLR.VPOSCLR bit must be set to 1.

51.3.3.3

The GLCDC has three interrupt request output signals (GR2UF, GR1UF, and VPOS) that correspond to the three states
above. Setting the corresponding bit in the INTEN register to 1 leads to the output of the interrupt request signal on
detection of the corresponding state. When the corresponding bit in the STCLR register is set to 1 and the corresponding
flag in the STMON register is cleared, or the corresponding bit in the INTEN register is set to 0 (disable interrupts) while
the interrupt request output signal is being output, the interrupt request signal can be negated.

51. Graphic LCD Controller (GLCDC)

Usage Notes
Setting the Priority Order of the Bus Masters

The GLCDC acquires graphics data from the frame buffer through internal main bus 2. The graphic 1 (GLCDC-GRA1)
and graphic 2 (GLCDC-GRA2) blocks in the GLCDC, the texture and RLE interface (DRW2D-TX) and display-list and
frame-buffer interface (DRW2D-FB) in the DRW2D, the EDMAC, DMAC, and DTC can operate as bus masters of the
internal main bus.
After a reset, the priority order of these bus masters is as follows:
GLCDC-GRA1 > DRW2D-TX > DRW2D-FB > GLCDC-GRA2 > EDMAC > DMAC > DTC.
In some cases, using the bus masters with this order of priority may lead to underflows of data for graphic 2. Change the
priority order of the bus masters as required.
For details, refer to section 16, Buses, or section 18, DMA Controller (DMACAa).
