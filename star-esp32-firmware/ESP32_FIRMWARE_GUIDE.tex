\section{Project Overview}
% =============================================================================

\subsection{Purpose}

The \texttt{star-esp32-firmware} project provides real-time motor control, sensor integration, and communication with the Raspberry Pi 5 gateway for the STAR robot platform. It runs on the ESP32-S3 microcontroller using FreeRTOS.

\subsection{Current Implementation Status}

\textbf{Component} & \textbf{Status} & \textbf{Notes} \\

STAR Framework Core & Complete & DIP architecture, interfaces \\
Bus Abstraction Layer & Complete & I2C, SPI, 1-Wire, SMBus, GPIO \\
Essential Drivers & \textbf{TODO} & BQ7850 (BMS), DS18B20 (Temp) drivers required \\
Error Handling & Complete & Retry logic with exponential backoff \\
Pin Validation & Complete & GPIO conflict detection \\
\hline
Motor Control (MCPWM) & \textbf{TODO} & Requires refactoring per guide \\
SPI Peripheral (Pi5 comm) & Complete & Low-level communication layer is ready \\
PID Controller & \textbf{TODO} & To be created as \texttt{lib/star\_pid} \\
Encoder Reading & \textbf{TODO} & To be created as \texttt{lib/star\_encoder} \\
\hline
\end{tabular}
\caption{Implementation Status Summary}
\end{table}

\section{Motor Control Architecture}
% =============================================================================

\subsection{Motor Control Refactoring Plan}

The \texttt{star\_motor} library currently handles all motor-related functionality. For improved modularity, testability, and clarity, it is recommended to refactor this monolithic library into three distinct components as originally envisioned. The following sections outline the proposed architecture for each module.

\subsubsection{\texttt{lib/star\_motor} (Proposed)}

This library should be responsible only for low-level motor control using the ESP32's MCPWM peripheral. Its sole focus is to abstract the hardware details of generating PWM signals.

\begin{enumerate}
    \item Create a clean interface with motor handle and configuration structs.
    \item Implement MCPWM initialization for 4 motors (2 MCPWM units, 2 operators each).
    \item Configure center-aligned (up-down count) mode for reduced EMI.
    \item Implement dead-time insertion to prevent H-bridge shoot-through.
    \item Add fault input handling for overcurrent protection.
\end{enumerate}

\textbf{Key Parameters:}
\begin{itemize}
    \item PWM Frequency: 20 kHz (above audible range)
    \item Dead Time: 500ns (DRV8243 requirement)
    \item Duty Cycle Resolution: 0.1\%
\end{itemize}

\begin{lstlisting}[language=C, caption=Proposed Motor Driver Interface]
typedef struct {
    mcpwm_unit_t unit;
    mcpwm_timer_t timer;
    gpio_num_t pwm_a;
    gpio_num_t pwm_b;
    gpio_num_t fault_pin;
    float max_duty;
} star_motor_config_t;

esp_err_t star_motor_init(star_motor_handle_t* handle,
                          const star_motor_config_t* config,
                          star_error_interface_t* error_iface);
esp_err_t star_motor_set_duty(star_motor_handle_t* handle, float duty_cycle);
esp_err_t star_motor_brake(star_motor_handle_t* handle);
esp_err_t star_motor_coast(star_motor_handle_t* handle);
\end{lstlisting}

\subsubsection{\texttt{lib/star\_encoder} (Proposed)}

This library would be dedicated to handling velocity feedback from the quadrature encoders.

\begin{enumerate}
    \item Use the ESP32 PCNT (Pulse Counter) peripheral.
    \item Configure for quadrature decoding (4x resolution).
    \item Implement velocity calculation from the count delta over time.
    \item Add overflow handling for the 16-bit hardware counter.
\end{enumerate}

\textbf{Encoder Specifications:}
\begin{itemize}
    \item Resolution: 341.2 counts/revolution
    \item Wheel diameter: 100mm
    \item Distance per count: 0.92mm
\end{itemize}

\subsubsection{\texttt{lib/star\_pid} (Proposed)}

This library should be a generic, reusable PID controller for closed-loop control. It should contain no hardware-specific code.

\begin{lstlisting}[language=C, caption=Proposed PID Controller Interface]
typedef struct {
    float kp, ki, kd;           % Gains
    float integral_limit;        % Anti-windup
    float output_limit;          % Max output
    float deadband;              % Ignore small errors
} star_pid_config_t;

void star_pid_init(star_pid_t* pid, const star_pid_config_t* config);
float star_pid_update(star_pid_t* pid, float setpoint, float measurement,
                      float dt);
void star_pid_reset(star_pid_t* pid);
\end{lstlisting}

\textbf{Initial Tuning Values (adjust experimentally):}
\begin{itemize}
    \item $K_p = 1.0$, $K_i = 0.5$, $K_d = 0.1$
    \item Loop rate: 1000 Hz
    \item Integral limit: $\pm$100
\end{itemize}

\subsection{Core Communication Interfaces}

\subsubsection{SPI Peripheral Driver}

The firmware implements SPI peripheral mode for communication with the Raspberry Pi 5.

\begin{itemize}
    \item \textbf{Mode:} Peripheral on SPI2 (HSPI)
    \item \textbf{Protocol:} Custom binary packet structure
    \item \textbf{Performance:} DMA is used for efficient, non-blocking transfers
\end{itemize}

\textbf{SPI Pin Mapping:}
\begin{table}[H]
\centering
\begin{tabular}{|l|l|l|}
\hline
\textbf{Signal} & \textbf{Pi5 GPIO} & \textbf{ESP32 GPIO} \\
\hline
COPI & GPIO11 & GPIO13 \\
CIPO & GPIO9 & GPIO12 \\
SCLK & GPIO11 & GPIO14 \\
CS & GPIO8 & GPIO15 \\
\hline
\end{tabular}
\end{table}

\textbf{Command Protocol:}
\begin{lstlisting}[language=C, caption=SPI Command Protocol]
// Command byte definitions
#define CMD_SET_VELOCITY    0x01  // Set wheel velocities
#define CMD_EMERGENCY_STOP  0x02  // Immediate stop
#define CMD_GET_ENCODERS    0x03  // Read encoder counts
#define CMD_GET_TELEMETRY   0x06  // Battery, temp, status

// Packet format: [CMD (1)] [LENGTH (1)] [DATA (N)] [CRC8 (1)]
typedef struct __attribute__((packed)) {
    uint8_t command;
    uint8_t length;
    uint8_t data[32];
    uint8_t crc8;
} spi_packet_t;

// Velocity command payload
typedef struct __attribute__((packed)) {
    float left_velocity;   // m/s
    float right_velocity;  // m/s
    uint32_t timestamp;    // ms since boot
} velocity_cmd_t;
\end{lstlisting}

\section{Extending the Bus Abstraction Layer}
% =============================================================================

To fully realize the Dependency Inversion Principle and support all required hardware (including ADCs and GPIO-controlled multiplexers), the \texttt{star\_bus} library must be extended. This section provides a detailed plan for this enhancement.

\subsection{Task 1: Re-create GPIO Bus Driver}
The GPIO bus driver is required to provide a standardized interface for controlling digital logic, such as the multiplexer for selecting ADC lines.

\subsubsection{Modify Type Definition Files}
\begin{enumerate}
    \item \textbf{File:} \texttt{lib/star\_bus/include/star\_bus\_common\_types.h} \\
    Add \texttt{k\_star\_bus\_type\_gpio} to the \texttt{star\_bus\_type\_t} enum.
    \item \textbf{File:} \texttt{lib/star\_bus/src/star\_bus\_types.c} \\
    Add the corresponding \texttt{"GPIO"} string to the \texttt{star\_bus\_type\_strings} array.
    \item \textbf{File:} \texttt{lib/star\_bus/include/star\_bus\_protocol\_types.h} \\
    Add the necessary GPIO configuration and operations structs.
\end{enumerate}
\begin{lstlisting}[language=C, caption=Additions to star\_bus\_protocol\_types.h]
/** @brief GPIO operations function pointers */
typedef struct {
    esp_err_t (*write_digital)(const struct star_bus_config* config, uint8_t pin_index, uint8_t value);
    esp_err_t (*read_digital)(const struct star_bus_config* config, uint8_t pin_index, uint8_t* value);
    /* Other GPIO ops like interrupts can be added here */
} star_gpio_ops_t;

/** @brief GPIO bus configuration */
typedef struct {
    gpio_num_t* pins;
    uint8_t pin_count;
    bool isr_installed;
    star_gpio_ops_t ops;
    /* Other config like callbacks can be added here */
} star_gpio_bus_config_t;

// Then, add star_gpio_bus_config_t to the star_bus_protocol_config_t union
typedef union {
    // ... existing i2c, spi, etc. structs
    star_gpio_bus_config_t gpio;
} star_bus_protocol_config_t;
\end{lstlisting}

\subsubsection{Create GPIO Driver}
\begin{enumerate}
    \item Create \texttt{lib/star\_bus/include/star\_bus\_gpio.h} to declare the public API for the GPIO bus, including the default ops initializer.
    \item Create \texttt{lib/star\_bus/src/star\_bus\_gpio.c}. This file will implement the GPIO logic using the ESP-IDF \texttt{driver/gpio.h} functions.
\end{enumerate}

\subsubsection{Update Bus Config Factory}
\begin{enumerate}
    \item \textbf{File:} \texttt{lib/star\_bus/include/star\_bus\_config.h} \\
    Add the function declaration for \texttt{star\_bus\_config\_create\_gpio()}.
    \item \textbf{File:} \texttt{lib/star\_bus/src/star\_bus\_config.c} \\
    Implement \texttt{star\_bus\_config\_create\_gpio()} and add the \texttt{k\_star\_bus\_type\_gpio} case to the \texttt{switch} statements in \texttt{star\_bus\_config\_init} and \texttt{star\_bus\_config\_deinit}.
\end{enumerate}

\subsubsection{Update Build System}
\begin{enumerate}
    \item \textbf{File:} \texttt{lib/star\_bus/CMakeLists.txt} \\
    Add \texttt{"src/star\_bus\_gpio.c"} to the \texttt{SRCS} list.
\end{enumerate}

\subsection{Task 2: Add ADC Bus Protocol}

This involves creating a new bus type for handling analog-to-digital conversions, following the established pattern in the library.

\subsubsection{Modify Type Definition Files}
\begin{enumerate}
    \item \textbf{File:} \texttt{lib/star\_bus/include/star\_bus\_common\_types.h} \\
    Add \texttt{k\_star\_bus\_type\_adc} to the \texttt{star\_bus\_type\_t} enum before the count.
    \item \textbf{File:} \texttt{lib/star\_bus/src/star\_bus\_types.c} \\
    Add the corresponding \texttt{"ADC"} string to the \texttt{star\_bus\_type\_strings} array.
    \item \textbf{File:} \texttt{lib/star\_bus/include/star\_bus\_protocol\_types.h} \\
    Add the necessary ADC configuration and operations structs.
\end{enumerate}
\begin{lstlisting}[language=C, caption=Additions to star\_bus\_protocol\_types.h]
/** @brief ADC operations function pointers */
typedef struct {
    esp_err_t (*read_raw)(const struct star_bus_config* config, int* out_raw);
    esp_err_t (*read_voltage)(const struct star_bus_config* config, int* out_voltage_mv);
} star_adc_ops_t;

/** @brief ADC bus configuration */
typedef struct {
    adc_oneshot_unit_handle_t unit_handle;
    adc_cali_handle_t cali_handle;
    adc_channel_t channel;
    adc_bitwidth_t bitwidth;
    adc_atten_t atten;
    star_adc_ops_t ops;
} star_adc_bus_config_t;

// Then, add star_adc_bus_config_t to the star_bus_protocol_config_t union
typedef union {
    // ... existing i2c, spi, gpio, etc. structs
    star_adc_bus_config_t adc;
} star_bus_protocol_config_t;
\end{lstlisting}

\subsubsection{Create ADC Driver}
\begin{enumerate}
    \item Create \texttt{lib/star\_bus/include/star\_bus\_adc.h} to declare the default ops initializer.
    \item Create \texttt{lib/star\_bus/src/star\_bus\_adc.c}. This file will implement the ADC logic using the ESP-IDF \texttt{adc\_oneshot} and \texttt{adc\_cali} drivers. It will define the functions for the \texttt{star\_adc\_ops\_t} struct.
\end{enumerate}

\subsubsection{Update Bus Config Factory}
\begin{enumerate}
    \item \textbf{File:} \texttt{lib/star\_bus/include/star\_bus\_config.h} \\
    Add the function declaration for \texttt{star\_bus\_config\_create\_adc()}.
    \item \textbf{File:} \texttt{lib/star\_bus/src/star\_bus\_config.c} \\
    Implement \texttt{star\_bus\_config\_create\_adc()} and add the \texttt{k\_star\_bus\_type\_adc} case to the \texttt{switch} statements in \texttt{star\_bus\_config\_init} and \texttt{star\_bus\_config\_deinit}.
\end{enumerate}

\subsubsection{Update Build System}
\begin{enumerate}
    \item \textbf{File:} \texttt{lib/star\_bus/CMakeLists.txt} \\
    Add \texttt{"src/star\_bus\_adc.c"} to the \texttt{SRCS} list.
\end{enumerate}

\subsection{Task 3: Implement Unified Bus Interface}

Create a true abstraction layer in the bus manager so that application code does not need to call protocol-specific functions.

\subsubsection{Add Generic Functions to Bus Manager}
\begin{enumerate}
    \item \textbf{File:} \texttt{lib/star\_bus/include/star\_bus\_manager.h} \\
    Declare new high-level, generic functions.
    \item \textbf{File:} \texttt{lib/star\_bus/src/star\_bus\_manager.c} \\
    Implement these functions. Each function will find the bus by name, verify its type, and call the appropriate function pointer from the bus's \texttt{ops} struct.
\end{enumerate}
\begin{lstlisting}[language=C, caption=Proposed Generic Interface in star\_bus\_manager.h]
/**
 * @brief Write a digital value to a bus (e.g., GPIO).
 */
esp_err_t star_bus_write_digital(star_bus_manager_t* manager, const char* bus_name, uint8_t value);

/**
 * @brief Read an analog value from a bus (e.g., ADC).
 * @param[out] out_voltage_mv The resulting voltage in millivolts.
 */
esp_err_t star_bus_read_analog_mv(star_bus_manager_t* manager, const char* bus_name, int* out_voltage_mv);

/**
 * @brief Perform a standard I2C/SPI write operation.
 */
esp_err_t star_bus_write(star_bus_manager_t* manager, const char* bus_name, uint8_t reg_addr, const uint8_t* data, size_t len);

/**
 * @brief Perform a standard I2C/SPI read operation.
 */
esp_err_t star_bus_read(star_bus_manager_t* manager, const char* bus_name, uint8_t reg_addr, uint8_t* data, size_t len);
\end{lstlisting}

This approach provides a clean, abstract, and extensible bus management system that fully adheres to the Dependency Inversion Principle.

\subsection{Task 4: Final Bus Library Cleanup}
As a final cleanup step, the unnecessary 1-Wire peripheral driver should be removed.
\begin{enumerate}
    \item Delete \texttt{lib/star\_bus/src/star\_bus\_onewire\_peripheral.c}.
    \item Delete the corresponding header file if it exists in \texttt{lib/star\_bus/include/}.
    \item Remove any references from the \texttt{CMakeLists.txt} file.
\end{enumerate}
\textbf{Reasoning:} The ESP32 will only act as a controller on the 1-Wire bus to communicate with the DS18B20 sensor. It will never need to act as a 1-Wire peripheral device.

\section{Testing Plan}

\subsection{Unit Tests}

\begin{enumerate}
    \item \textbf{PID Controller}: Test with simulated plant, verify convergence
    \item \textbf{Encoder Driver}: Test count accuracy, overflow handling

\begin{enumerate}

    \item \textbf{SPI + Motor}: Command-to-motion latency measurement

\section{Build and Flash Instructions}
% =============================================================================

\subsection{Prerequisites}

\begin{lstlisting}[language=bash]
# Install PlatformIO
pip install platformio

# Install ESP-IDF (handled by PlatformIO)
pio pkg install
\end{lstlisting}

\subsection{Build Commands}

\begin{lstlisting}[language=bash]
# Build for ESP32-S3
pio run -e esp32s3

# Build for ESP32-WROOM (dev board)
pio run -e esp32_wroom

# Upload firmware
pio run -e esp32s3 --target upload

# Monitor serial output
pio device monitor -b 115200
\end{lstlisting}

\subsection{Configuration}

Edit \texttt{sdkconfig.esp32s3} for production settings:
\begin{itemize}
    \item Enable brownout detection
    \item Set CPU frequency to 240 MHz
    \item Configure flash size (16 MB)
    \item Enable PSRAM if needed
\end{itemize}
