Phase 1 -- audit the existing USB code against the manual:
  1. Walk every constant in libs/rx_usb/inc/rx_usb.h and the bare-metal

     the manual page or section in the doc-comment. Any constant that

  2. Verify the USB clock setup. RX72N feeds USB0 from UCK = 48 MHz
     derived from PLL. SYSTEM.SCKCR.UCK[3:0] picks the divider; PLL
     output / UCK = 48 MHz. Cross-check rx_clock_power_init.c against
     manual chapter 9 (clock generation) + chapter 25 (USB).
  3. Verify pin map. STAR PCB USB pins: confirm DP, DM, VBUS, VBUSEN

     fix on feat/main relies on).

Coding style -- MUST follow /workspaces/STAR/CLAUDE.md. The existing
libs/rx_usb/ on feat/usb0 was written before the round-2 audit; some of
it predates the current style rules. Any NEW code you add must follow
the rules; existing code you TOUCH must be brought up to the rules in
the same edit (don't leave half the file modern and half legacy).

- All headers use `#pragma once` (no traditional include guards).
- All files pure 7-bit ASCII (no em-dashes, no Unicode tree drawings,
  no smart quotes). The pre-commit hook + CI ASCII Check will reject
  the commit otherwise. Use `--` for em-dashes and `|--` `` `-- `` for
  tree drawings if any.
- Naming:  functions/vars `snake_case`,  types `snake_case_t`,
  static/file-scope vars `s_<name>`,  static (testable) functions
  `internal_<name>`,  private helpers `priv_<name>`,  globals avoided
  (and `g_` if unavoidable).
- ZERO magic numbers. Every numeric literal -- including pipe numbers,
  endpoint addresses, register offsets, FIFO sizes -- MUST be a C23
  typed enum with an explicit underlying type:
      typedef enum : uint8_t  { ... } foo_t;
      typedef enum : uintptr_t{ k_xxx_base = 0x000A0000, ... } addresses_t;
  Use `uintptr_t` for register-base-address enums (NOT uint32_t -- it
  silently truncates on the 64-bit unit-test host).
- Hardware register access via inline accessors that return
  `volatile <type> *` (NOT macros). USB0 should get its own
  `usb0()` accessor in rx72n_usb_regs.h matching the pattern of mtu1(),
  tpu_control(), etc.
- NASA Power of 10:
    1. No goto / setjmp / recursion.
    2. All loops have static upper bounds (use the typed enum).
    3. No dynamic allocation after init -- everything static.
    4. Functions ~60 lines max (clang-tidy CI fails at 60+). USB ISRs
       and big bulk-IN handlers must be split.
    5. At least 2 pre-conditions and 2 post-conditions per function.
    7. Every function-call return value either checked or explicitly
       cast to (void).  Use RX_RETURN_ON_ERROR.
   10. -Wall -Wextra -Werror; CI fails on any warning.
- Doxygen on every file/function/struct/enum/var/typedef/macro you
  add. ALL applicable tags. Reference rx_pid_compute() as canonical.
  Minimum per fn: @brief, @details, @param, @return, @retval, @pre,
  @post, @note, @see, @since.
- Inclusive terminology: Controller / Peripheral, COPI / CIPO, CS,
  Primary / Main. USB has its own legitimate "Host / Function" or
  "Host / Device" terminology -- those are USB-spec terms, fine to
  keep. Just avoid master/slave for any non-USB thing the driver
  touches.
- No backward-compatibility shims (no deprecated aliases for
  pre-rebase function names). Per CLAUDE.md "Backward Compatibility
  Policy": zero compat layers.
- Run `python3 scripts/utils/fix-encoding.py --check <file>` on every
  file you touch before committing.
- Run clang-format-15 on every .c/.h you touch before committing.
