   - Frequency-to-prescaler formula: PRE_SCALE = (25MHz / (4096 × freq)) - 1

5. MODE REGISTER SPECIFICATIONS
   - MODE1 (0x00): RESTART, EXTCLK, AI, SLEEP, SUB3, SUB2, SUB1, ALLCALL
   - MODE2 (0x01): INVRT, OUTDRV, OUTNE[1:0] bits explained
   - Initialization sequence (SLEEP→EXTCLK→AI→RESTART)
   - Timing requirements (500 µs oscillator startup delay)
   - Read-modify-write patterns for safe register updates

6. LED OUTPUT REGISTERS ANALYSIS
   - 12-bit ON/OFF counter values per channel
   - 4-register layout per channel (ON_L, ON_H, OFF_L, OFF_H)
   - 12-bit counter cycle (0x000 to 0xFFF = 4096 steps)
   - PWM logic: output high when counter ≥ ON and < OFF
   - Duty cycle calculation: (OFF - ON) / 4096 × 100%
   - Critical limitation: ON must not equal OFF (hardware constraint)

KEY TECHNICAL FINDINGS
================================================================================

REGISTER MAP:
- MODE1 (0x00): 8 control bits for device operation
- MODE2 (0x01): 3 control bits for output configuration
- PRE_SCALE (0xFE): 8-bit frequency divider
- LED0-LED15: 64 bytes (16 channels × 4 bytes)
- Special registers: SUBADR1-3, ALLCALLADR, ALL_LED

FREQUENCY SPECIFICATIONS:
- Minimum: 24 Hz (prescale=255)
- Default: 200 Hz (prescale=30)
- Common: 50 Hz (servo), 1000 Hz (LED)
- Maximum: 1526 Hz (prescale=3)
- Formula: freq = 25MHz / (4096 × (prescale+1))

PWM SPECIFICATIONS:
- Resolution: 12-bit (0-4095 steps)
- Channels: 16 independent outputs
- Duty Cycle: (OFF - ON) / 4096 × 100%
- Phase Shift: Adjustable via ON register offset
- Special Values: 0x1000 for full ON/OFF

I2C SPECIFICATIONS:
- Slave Addresses: 62 configurable (0x40-0x7E)
- Broadcast: 0xE0 (All Call)
- Groups: 3 subaddresses (0xE2, 0xE4, 0xE8)
- Bus Speed: Standard (100 kHz) or Fast (400 kHz) recommended
- Auto-Increment: Supported for multi-register access

SECURITY FINDINGS:
1. Address conflicts possible with identical configurations
2. Invalid register writes not prevented by device
3. Frequency overflow possible in calculations
4. Hardware limitation: ON != OFF enforced by software
5. I2C bus snooping possible (physical access required)
6. No authentication mechanisms in I2C protocol
7. Timing attacks possible on PWM patterns
8. DoS via bus flooding or line holding

MEMORY SAFETY FINDINGS:
1. Integer overflow in prescaler calculation (mitigated: float)
2. Buffer overflow in array writes (mitigated: bounds check)
3. NULL pointer dereference (mitigated: validation)
4. Use-after-free from improper cleanup (mitigated: flags)
5. Double-free on deinit (mitigated: state tracking)
6. Register address calculation overflow (mitigated: validation)
7. Uninitialized register reads (mitigated: cache/reread)

================================================================================
KNOWN LIMITATIONS
================================================================================

HARDWARE LIMITATIONS:
- 12-bit resolution maximum (cannot exceed 4096 steps)
- Frequency range 24-1526 Hz (cannot go lower or higher)
- ON value cannot equal OFF value (device limitation)
- I2C-only interface (no SPI option)
- Single master only (standard I2C)

SOFTWARE CONSIDERATIONS:
- Floating-point math required for safe prescaler calculation
- I2C timeouts possible with slow clock speeds
- Frequency changes briefly pause all outputs (SLEEP cycle required)
- Some register changes require SLEEP mode
- Auto-increment feature must be enabled for burst writes

APPLICATION CONSTRAINTS:
- I2C bus speed affects update rate
- Number of devices limited by I2C bus (62 maximum)
- Total current draw limited by power supply
- All channels share same frequency
- Subaddresses cannot overlap with main addresses
