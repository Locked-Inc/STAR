KEY TECHNICAL SPECIFICATIONS
================================================================================

PROTOCOL TIMING:
  - Initialization LOW: 1-10ms (minimum 1ms)
  - Initialization HIGH: 20-40μs
  - Sensor response LOW: 80μs
  - Sensor response HIGH: 80μs
  - Bit LOW (all bits): 50μs
  - Bit 0 HIGH: 26-28μs
  - Bit 1 HIGH: ~70μs (approximately)
  - Sampling interval: 2000ms minimum between reads
  - Total transmission time: ~5-6 milliseconds

40-BIT DATA FORMAT:
  - Byte 0: Humidity integer (high byte)
  - Byte 1: Humidity decimal (low byte)
  - Byte 2: Temperature integer (high byte)
  - Byte 3: Temperature decimal (low byte)
  - Byte 4: Checksum (last 8 bits of sum)

DATA INTERPRETATION:
  - Humidity = ((Byte0 << 8) | Byte1) / 10.0
  - Temperature = (int16_t)((Byte2 << 8) | Byte3) / 10.0
  - Checksum = (Byte0 + Byte1 + Byte2 + Byte3) & 0xFF

CRITICAL IMPLEMENTATION DETAIL:
  Use int16_t for temperature to correctly handle negative values
  via two's complement representation. This is the most common bug
  in DHT22 implementations (sign-magnitude vs two's complement).

================================================================================
SECURITY & SAFETY CONSIDERATIONS
================================================================================

1. TOCTOU RACE CONDITIONS (GPIO Race)
   - Issue: GPIO state checked, then modified between check and use
   - Risk: Corrupted timing measurements, wrong bit interpretation
   - Mitigation: Disable interrupts with portENTER_CRITICAL()
   - Cost: ~10ms interrupt latency (acceptable for 2-second sampling)

2. CHECKSUM TIMING ATTACKS (Theoretical)
   - Issue: Validation timing could leak information
   - Risk: Very low (non-cryptographic, IoT sensor)
   - Mitigation: Constant-time comparison (optional)
   - Recommendation: Skip for DHT22 (not security-critical)

3. GPIO INTERRUPT DELAYS
   - Issue: WiFi/LWIP can delay interrupts by 50-100μs
   - Risk: Timing thresholds become unreliable
   - Mitigation: Conservative timing margins
   - Thresholds: 18-35μs for 0-bit, 60-85μs for 1-bit

4. BUFFER OVERFLOW IN BIT ASSEMBLY
   - Issue: Reading 40 bits without bounds checking
   - Risk: Infinite loop if sensor hangs
   - Mitigation: Timeout protection (250ms maximum)
   - Implementation: CPU cycle counter with limits

5. SAMPLING PERIOD VIOLATIONS
   - Issue: DHT22 can hang if polled faster than 2 seconds
   - Risk: Sensor becomes unresponsive
   - Mitigation: Enforce 2-second minimum interval
   - Implementation: Track last_read_time

6. MULTICORE INTERFERENCE
   - Issue: Dual-core ESP32 can race on GPIO operations
   - Risk: Timing measurements corrupted by other core
   - Mitigation: portENTER_CRITICAL_ISR() for strict sync
   - Alternative: Pin ownership model

================================================================================
TEMPERATURE HANDLING - CRITICAL BUG
================================================================================

WRONG APPROACH (Many implementations):
  int16_t temp = (int16_t)((data[2] << 8) | data[3]);
  if (data[2] & 0x80) {
      temp = -(temp & 0x7FFF);  // SIGN-MAGNITUDE (WRONG!)
  }

RESULT FOR -16.2°C (0xFF5E):
  Incorrectly interprets as: -9.4°C (WRONG)

CORRECT APPROACH:
  int16_t temp_raw = (int16_t)((data[2] << 8) | data[3]);
  float temperature = temp_raw / 10.0f;  // TWO'S COMPLEMENT (CORRECT)

RESULT FOR -16.2°C (0xFF5E):
  Correctly interprets as: -16.2°C (CORRECT)

KEY INSIGHT:
  The DHT22 uses two's complement encoding for negative temperatures.
  Simply cast to int16_t and divide by 10. The int16_t type
  automatically handles the two's complement interpretation.

COMMON MISTAKES & FIXES
================================================================================

MISTAKE 1: Wrong temperature sign handling
  WRONG: temperature = data[2] & 0x7F; if (data[2] & 0x80) temp = -temp;
  RIGHT: int16_t temp = (int16_t)((data[2] << 8) | data[3]); float t = temp/10.0;

MISTAKE 2: No critical section protection
  WRONG: while (gpio_get_level(pin) == 0) count++;
  RIGHT: portENTER_CRITICAL(&mux); { while (gpio_get_level(pin) == 0) count++; } portEXIT_CRITICAL(&mux);

MISTAKE 3: Sampling too fast
  WRONG: for (int i = 0; i < 100; i++) dht22_read();
  RIGHT: vTaskDelay(2000 / portTICK_PERIOD_MS); dht22_read();

MISTAKE 4: No checksum validation
  WRONG: read_bits(data); temperature = ((data[2] << 8) | data[3]) / 10.0;
  RIGHT: if ((data[0] + data[1] + data[2] + data[3] & 0xFF) != data[4]) return ERROR;

MISTAKE 5: No timeout protection
  WRONG: while (gpio_get_level(pin) == 0);
  RIGHT: uint32_t start = xthal_get_ccount(); while (gpio_get_level(pin) == 0) { if ((xthal_get_ccount() - start) > max_cycles) return TIMEOUT; }
