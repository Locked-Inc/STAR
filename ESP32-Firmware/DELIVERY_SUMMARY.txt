KEY RESEARCH FINDINGS
================================================================================

1. TIMING SPECIFICATIONS
   - Trigger pulse: 10 μs minimum (TTL 5V)
   - Echo response: 150 μs to 25 ms (2 cm to 400 cm)
   - Response delay: 200-300 μs after trigger
   - Recommended measurement cycle: 60+ ms
   - Maximum frequency: 50 Hz (20 ms minimum)

   Source: Official HC-SR04 datasheets (SparkFun, Handsontec, MPJA)

2. MEASUREMENT RANGE & ACCURACY
   - Measurement range: 2 cm to 400 cm
   - Accuracy: ±3 mm (optimal conditions)
   - Practical accuracy: ±1-2 cm
   - Typical jitter: 2-4 cm indoors (unfiltered)
   - Detection angle: ±15 degrees

   Source: DataSheets from multiple distributors

3. DISTANCE CALCULATION FORMULAS
   - Simple: Distance (cm) = Echo_Width (μs) / 58
   - With temperature: Adjusted for speed of sound variation
   - Speed formula: v = 331.4 + 0.606 * T (Celsius)
   - Temperature impact: 0.2%/°C variation

   Source: Physics formulas, ISO 9613-1 standard

4. TEMPERATURE COMPENSATION
   - At 0°C: 331.4 m/s (±2.2 cm error vs 20°C reference)
   - At 20°C: 343.2 m/s (reference)
   - At 40°C: 355.0 m/s (±2.2 cm error)
   - Temperature sensors: DS18B20, DHT22, HTU21
   - Compensation strategy: Update temperature every 5-10 measurements

   Source: Community implementations, physics references

5. ESP32 TIMING CHARACTERISTICS
   - Interrupt latency (no WiFi): 2-10 μs
   - Interrupt latency (WiFi active): 50-100 μs
   - GPIO rise/fall time: <1 μs
   - Timer resolution: 1 μs
   - Critical sections: Use portDISABLE_INTERRUPTS()

   Source: Espressif ESP32 Technical Reference Manual, FreeRTOS docs

6. GPIO LEVEL SHIFTING REQUIREMENTS
   - HC-SR04 outputs: 5V TTL
   - ESP32 maximum: 3.3V
   - Solution: Voltage divider (3.3kΩ / 2.2kΩ) → 2.0V output
   - Output impedance: ~120 Ω (requires pull-up resistor)

   Source: Electrical characterization from datasheets

7. EDGE CASES AND FAILURES
   - No echo: Timeout after 30 ms (>400 cm or sensor failure)
   - Noise: Short pulses <116 μs rejected as noise
   - Multiple echoes: First echo captured (shortest distance)
   - Cross-talk: Affects multiple sensors in close proximity
   - Solutions: Median filtering, time staggering, 60+ ms cycles

   Source: Field observations and community forums

8. SECURITY CONSIDERATIONS
   - TOCTOU vulnerability: Atomic snapshot prevents time-of-check/use attacks
   - Race conditions: Atomic operations prevent ISR/main code conflicts
   - Input injection: Bounds checking and plausibility verification
   - Memory safety: Overflow protection, buffer boundaries
   - Interrupt safety: ISR handlers minimal, IRAM-based

   Source: CWE databases, Espressif security guidelines

9. IMPLEMENTATION BEST PRACTICES
   - Use interrupt mode for non-blocking measurements
   - Apply median filter to reduce noise (±3-4 cm jitter typical)
   - Enable temperature compensation for >1 cm accuracy requirement
   - Implement plausibility checking (reject >50 cm changes)
   - Use 60+ ms between measurements to prevent cross-talk

   Source: Successful community implementations, industrial applications

10. CRITICAL TIMING VERIFICATION
    - ESP32 can reliably measure 1 μs resolution
    - ISR-based edge detection achieves 2-10 μs accuracy
    - Polling method less accurate but adequate for most uses
    - WiFi causes 50-100 μs latency (acceptable with filtering)

    Source: Implementation testing and validation

================================================================================
SECURITY FEATURES IMPLEMENTED
================================================================================

1. TOCTOU PREVENTION
   - Problem: Value could change between check and use
   - Solution: Atomic snapshot during measurement
   - Implementation: portDISABLE_INTERRUPTS() during critical sections

2. RACE CONDITION PREVENTION
   - Problem: ISR and main code access same variables
   - Solution: atomic_load() and atomic_store() for 32-bit values
   - Alternative: Mutex/semaphore for complex access patterns

3. INPUT VALIDATION
   - Echo width bounds: 116-23,200 μs (2-400 cm)
   - Plausibility checking: Reject >50 cm changes between measurements
   - Noise rejection: Pulses <116 μs treated as electrical noise
   - Saturation handling: Out-of-range values mapped to error codes

4. MEMORY SAFETY
   - Integer overflow: Use 32-bit intermediates for 16-bit inputs
   - Timer overflow: Signed arithmetic for wrap-around safe comparison
   - Stack overflow: ISR uses minimal local variables
   - Buffer overflow: Bounds checking in filter/stats functions

5. INTERRUPT SAFETY
   - ISR execution time: <1 μs (minimal processing)
   - IRAM placement: Functions marked IRAM_ATTR for RAM execution
   - No blocking calls: No mutexes, only atomic operations in ISR
   - ISR re-entrancy: Safe due to minimal state modification

================================================================================
MEMORY SAFETY ANALYSIS
================================================================================

Memory Issues Addressed:
1. Timer Overflow (32-bit wraparound)
   - Vulnerability: Timeout comparison fails after 49+ days
   - Solution: Use signed arithmetic for overflow-safe comparison
   - Implementation: if ((int32_t)(current - deadline) > 0)

2. Integer Overflow (distance calculation)
   - Vulnerability: echo_us (16-bit) * 343 overflows
   - Solution: Use 32-bit for intermediates
   - Implementation: (uint32_t)echo_us * 343 / 2000000

3. Stack Overflow (ISR context)
   - Vulnerability: Large local arrays in ISR
   - Solution: Use static/global buffers
   - Implementation: Minimal stack use in ISR handlers

4. Buffer Overflow (measurement storage)
   - Vulnerability: Array index exceeds bounds
   - Solution: Bounds checking before write
   - Implementation: Circular buffer with modulo indexing

5. Struct Padding (memory corruption)
   - Vulnerability: Uninitialized padding bytes
   - Solution: Explicit memset() of structures
   - Implementation: memset(&sensor, 0, sizeof(sensor))

================================================================================
EDGE CASE HANDLING
================================================================================

1. No Echo Received (Timeout)
   - Cause: Object >400 cm or sensor failure
   - Detection: 30 ms timeout
   - Recovery: Return HC_SR04_ERR_TIMEOUT
   - User action: Retry or diagnose sensor

2. Electrical Noise (False Pulses)
   - Cause: EMI from motors, WiFi, or power supplies
   - Detection: Pulse width <116 μs
   - Recovery: Reject as HC_SR04_ERR_INVALID_PULSE
   - Mitigation: Decoupling capacitor, shielding

3. Multiple Echoes (Reflections)
   - Cause: Sound reflects from multiple surfaces
   - Detection: First echo (shortest) is valid
   - Recovery: Disable ISR after first echo
   - Limitation: Cannot measure multi-path scenarios

4. Cross-Talk (Multiple Sensors)
   - Cause: Sensors interfere with each other
   - Detection: Measurements from nearby sensors overlap
   - Recovery: Stagger trigger timing (10+ ms apart)
   - Solution: Use 60+ ms measurement cycles

5. Temperature Drift
   - Cause: Ambient temperature changes
   - Effect: ±0.2% error per 1°C variation
   - Recovery: Update temperature reading before each measurement
   - Solution: Integrate external temperature sensor

6. Rapid Distance Changes
   - Cause: Object moving quickly or measurement error
   - Detection: >50 cm change between measurements
   - Recovery: Reject as HC_SR04_ERR_IMPLAUSIBLE_CHANGE
   - Solution: Implement object tracking algorithm
